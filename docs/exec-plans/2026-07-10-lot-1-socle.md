# Lot 1 - Socle technique

## Objectif

Créer le socle exécutable du projet **Les Routes Oubliées** :

* application Angular dans `frontend/` ;
* application Spring Boot dans `backend/` ;
* configuration PostgreSQL et Flyway ;
* commandes de développement et validation initiales ;
* conteneurisation de développement alignée avec `infra/compose.yml`.

Le lot ne doit pas implémenter les règles métier détaillées des lots suivants. Il doit fournir une base saine, testable et maintenable.

L'orchestrateur principal conserve l'intégration.

Sous-agents en lecture seule :

* Qualité/Sécurité : vérifier les validations minimales, secrets, Actuator, conteneurs et `.gitignore`.

Écriture locale par l'orchestrateur :

## Risques

* Node/npm ne sont pas installés localement.
* Java local est en version 17 alors que le projet impose Java 25.
* Les générateurs et builds nécessitent des téléchargements réseau.
* Angular 22 et Spring Boot 4.1.x doivent être disponibles dans les dépôts utilisés.
* Les tests complets peuvent être impossibles sans images Docker ou dépendances téléchargées.

Approche retenue :

* privilégier Docker pour les générateurs et validations afin de ne pas installer d'outils globalement ;
* demander une autorisation réseau lorsque nécessaire ;
* documenter clairement toute validation non exécutée.

## Bilan d'execution

Statut : socle cree et validations principales effectuees avec limites documentees.

Sous-agents utilises :

* Frontend : revue de structure Angular, scripts, accessibilite initiale et Dockerfile.
* Backend : revue de structure Spring Boot, Java 25, PostgreSQL/Flyway et tests initiaux.
* Qualite/Securite : revue Compose, secrets, exposition PostgreSQL, CSRF, Actuator et conteneurs.

Decisions prises :

* utiliser Docker comme voie de validation principale, car Node/npm ne sont pas installes localement et Java local est en version 17 ;
* conserver un monolithe Spring Boot et une SPA Angular servis par deux conteneurs applicatifs separes en developpement ;
* exposer PostgreSQL uniquement sur `127.0.0.1` en developpement ;
* utiliser `postgres:18` avec le volume monte sur `/var/lib/postgresql`, conforme au comportement de l'image PostgreSQL 18 ;
* utiliser `nginxinc/nginx-unprivileged` pour servir le frontend sans processus root.

Validations executees :

* `docker compose -f infra/compose.yml config` : OK ;
* `docker compose -f infra/compose.yml --profile app config` : OK ;
* `docker compose -f infra/compose.yml --profile app build` : OK ;
* `docker compose -f infra/compose.yml up -d db` puis verification de sante PostgreSQL : OK ;
* `docker run ... npm run lint` dans `frontend/` : OK ;
* `docker run ... npm run build` dans `frontend/` : OK ;
* `docker run ... sh ./mvnw -B -DskipTests package` dans `backend/` avec Java 25 : OK ;
* `git diff --check` : OK.

Limites constatees :

* `npm test -- --watch=false` echoue dans Docker avant execution des tests, sur un timeout de demarrage des workers Vitest ;
* `./mvnw verify` n'a pas ete execute localement car Java local est en version 17 au lieu de Java 25 ;
* la verification backend complete avec Testcontainers reste a finaliser quand l'environnement Java 25/Docker sera stabilise ;
* `npm install` signale 3 vulnerabilites faibles dans les dependances frontend generees.
