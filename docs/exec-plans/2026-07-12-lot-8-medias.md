# Lot 8 - Medias

## Objectif

Implanter la gestion MVP des medias uploades : stockage persistant configurable, validation stricte des images, mediatheque admin minimale, service public controle et premiers rattachements aux contenus.

## Perimetre

- Backend : table `media_assets`, entite et repository, service de stockage, upload admin, liste admin, consultation publique par identifiant, suppression controlee, tests.
- Frontend : service API medias et interface admin minimale pour lister, ajouter et supprimer les images avec texte alternatif.
- Documentation : consigner les choix de validation et les limites restantes du rattachement aux contenus.

## Hors perimetre

- Galerie avancee, recadrage ou optimisation d'images.
- Upload des cartes geographiques, qui restent des assets versionnes.
- Audit complet des actions, prevu dans le lot 9.
- Editeur Markdown riche avec insertion assistee depuis la mediatheque.

## Risques

- Accepter un fichier non image ou un SVG deguise.
- Exposer un chemin systeme ou permettre une traversee de repertoires.
- Supprimer un media encore reference par un contenu.
- Rendre l'administration de medias difficile au clavier ou sans texte alternatif.

## Criteres d'acceptation

- Un administrateur authentifie peut uploader une image PNG, JPEG ou WebP avec texte alternatif.
- Les fichiers recus sont stockes sous un nom serveur genere dans le dossier configure.
- L'API refuse les formats interdits, les tailles excessives, les fichiers vides et les contenus dont la signature ne correspond pas au MIME annonce.
- Un media public est servi par une route backend controlee avec type MIME serveur et `X-Content-Type-Options: nosniff`.
- L'administration liste les medias sans exposer de chemin systeme.
- La suppression est refusee lorsqu'un media est reference par un contenu connu.
- Les routes admin restent protegees et les routes publiques n'exposent aucun brouillon ni donnee sensible.
